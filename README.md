# Reading loan files by hand: keeping the officer in charge

A one-page design case study on redesigning a document-based loan assessment workflow for housing microfinance. An AI system does the reading and flagging, a simple scorecard recommends, and a loan officer stays the decision-maker. It is a work sample for a human-AI collaboration design role and shows how a workflow can be analysed, redesigned with AI, kept under human control and tested.

**Read the result:** [case_study.pdf](case_study.pdf) (one A4 page). The same text is in [case_study.md](case_study.md) and [case_study.docx](case_study.docx).

## Honesty note

- **This is a design case.** The workflow is a proposed design built on my published, preregistered study. It is not deployed at Habitat for Humanity or at any lender, and no loan officer has used it.
- **The starting workflow is a generic, simplified model.** It is built from public sources and general knowledge of lending work, and it does not describe any lender or any Habitat process.
- **Only real evidence counts as evidence.** Every number on the page comes from the study repository or from a source I opened and read. Nothing is invented: no adoption figures, no time saved, no user quotes, no interviews. The study figures were also recomputed from the study's per-decision data files (`docs/evidence.md`).
- **The user test is a plan.** `docs/test_plan.md` describes it. No test has been run, so there is no results file.
- **The evidence has limits.** The study used synthetic consumer-credit documents, three small open models and no human reviewers, and it measured no fairness effects. Housing loan files, real documents and real loan officers are outside it. `docs/evidence.md` section 7 lists the gaps.
- **Public information only.** Claims about Habitat for Humanity and housing microfinance rest on the six sources in `docs/sources.md`, each opened and checked, with what it supports and what it does not.

## How the page was produced

The author approved the study figures before they were used. Steps, in order:

1. **Evidence.** Read the study paper and repository. Recomputed the headline figures from the study's decision files. Listed the paper's inconsistencies and the figures to leave out (`docs/evidence.md`).
2. **Sources.** Opened six public sources and checked each quoted phrase (`docs/sources.md`).
3. **Current workflow.** Eight steps, each tagged as sourced or "typical, not measured" (`docs/current_workflow.md`).
4. **Redesign.** The eight steps with who or what does each, what the human does and the control that protects the person (`docs/redesigned_workflow.md`).
5. **Diagram.** Generated by `build/make_diagram.py` as SVG, rendered to PNG. Black and one navy accent, no icons.
6. **Test plan.** Questions, participants, materials, measures, and pass and stop rules fixed in advance (`docs/test_plan.md`).
7. **The page.** `build/build_case_study.js` holds the text once and writes the Markdown and the DOCX. `build/embed_fonts.py` embeds Computer Modern in the DOCX. LibreOffice renders the PDF. `build/build.sh` fails unless the PDF is exactly one page.
8. **Review.** Every sentence traced to evidence, banned style patterns searched, plain-language check (`docs/review_log.md`).

The landing page `index.html` is built from `site/landing.json` by `tools/make_landing.py`, the generator shared with the study's own page.

## Rebuilding

Needs Node with the `docx` package, Python with `fonttools`, LibreOffice and poppler. The font is CMU Serif (Computer Modern Unicode, SIL Open Font License), not included here. Download `cmunrm`, `cmunbx`, `cmunti` and `cmunbi` as `.otf` files from https://mirrors.ctan.org/fonts/cm-unicode/fonts/otf/ and run:

```
python3 build/make_diagram.py diagram/workflow.svg
FONT_DIR=/path/to/fonts bash build/build.sh
python3 tools/make_landing.py site/landing.json - index.html
```

The diagram PNG is a render of the SVG at 2400 pixels wide. `build.sh` loads the fonts through a throwaway LibreOffice profile, so nothing is installed on the system.
